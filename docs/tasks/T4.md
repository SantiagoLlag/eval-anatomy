# T4 — "Your eval" view and linter

**Depends on:** T2, T3. **Branch:** `t4-your-eval`.

## Goal
Show a concrete eval mapped onto the anatomy and review it against `content/best-practices.json`.

## Read first
`docs/ARCHITECTURE.md` (Linter, Diagrams, Routes), `content/best-practices.json`, `src/lib/coverage.ts`, `src/components/anatomy/*`, `docs/reference/agents-visualizer/src/lib/lint/*`.

## Deliverables
1. `src/lib/lint/`: engine + `deterministicRules.ts` with one function per `deterministic` rule id, implementing its `check` text against `EvalCard`; `appliesIf` evaluation (taxonomy values, `parts`, `catalog`). One pass test and one fail test per rule. A test fails if a deterministic rule in the JSON has no implementation.
2. `POST /api/lint/llm`: runs all applicable `llm-judge` rules in one structured call; returns findings with a quoted span as evidence. Same key handling as `/api/decompose`.
3. Tab "Anatomy" on `/catalog/[id]` and `/inspect`: `AnatomyDiagram` with `overlay`; clicking a part shows the theory panel side by side with **what this eval has** for that part (the card fields, rendered readably) and its findings.
4. Tab "Review": findings grouped by part and severity, each with statement, rationale, sources; `human` rules as a checklist; a score-free summary ("3 errors, 5 warnings, 2 info"). No single numeric grade.
5. `/inspect`: drop zone + paste box + format picker (pre-filled by `detectFormat`), "Decompose with Claude" button for free text (shown only when a key is available; field to paste a key, kept in memory only), "Save as eval.md".

## Acceptance
- Both seeds render with coverage and findings; the `promptfoo.yaml` fixture pasted into `/inspect` renders without an API key.
- All deterministic rules implemented and tested.

## Out of scope
Flow diagram (T5), catalog list (T6).
