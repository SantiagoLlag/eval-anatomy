# T6 — Catalog, export and contribution flow

**Depends on:** T2. **Can run in parallel with:** T4, T5. **Branch:** `t6-catalog`.

## Goal
Browse, filter, use and contribute evals.

## Read first
`docs/ARCHITECTURE.md` (Routes, Content model → taxonomy), `docs/FORMAT.md`, `CONTRIBUTING.md`, `content/taxonomy.json`, `content/tools.json` (promptfoo fields).

## Deliverables
1. `/[locale]/catalog`: cards (name, summary, language, taxonomy chips, counts of present parts, linter error count), filters = taxonomy axes with `filter: true` (multi-select where `multiple`), text search, URL-synced filter state.
2. `/[locale]/catalog/[id]`: header (identity, authors, license, version, status), tabs from T4/T5 plus "Card" (rendered Markdown body, relative links to `scripts/` and `examples/` resolved to GitHub URLs) and "Source" (raw eval.md).
3. Export: download `eval.md`; **export to promptfoo YAML** (`promptfooconfig.yaml`) mapping parts → fields per `tools.json` (criteria → `assert` with `llm-rubric` or code assertions where possible, cases → `tests`, threshold → `threshold`); unmapped parts listed as comments. Round-trip test: export the canonical running example and re-import with the T2 promptfoo parser.
4. Contribution: `.github/ISSUE_TEMPLATE/new-eval.yml`, `.github/pull_request_template.md` with a checklist (validates, license, no personal data, sources for claims); CI comment on PRs that touch `catalog/` with the linter summary for the changed eval (GitHub Action using the app's lint engine via a small node script `scripts/lint-catalog.ts`).
5. "Add your eval" page section: link to FORMAT.md, `/inspect` → "Save as eval.md" → open a PR.

## Acceptance
- Filters narrow correctly on the two seeds plus 3 throwaway test cards (in test fixtures, not in `catalog/`).
- promptfoo export of both seeds is valid YAML and re-imports.

## Out of scope
User accounts, ratings, server-side storage.
