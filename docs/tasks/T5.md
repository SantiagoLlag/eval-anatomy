# T5 — Flow view

**Depends on:** T2. **Can run in parallel with:** T4, T6. **Branch:** `t5-flow-view`.

## Goal
A diagram of how a concrete eval runs, from cases to decision.

## Read first
`docs/ARCHITECTURE.md` (Diagrams → Flow view), `content/anatomy.json` (relations), `docs/reference/agents-visualizer/src/lib/layout/autoLayout.ts`, `src/components/canvas/*`.

## Deliverables
1. `src/lib/flow/buildFlowGraph.ts`: pure `EvalCard → {nodes, edges}` as specified; one node per grader fed by its criteria; reference edges only into graders that use a reference; validation as an external dashed edge into judge nodes with a TPR/TNR badge when present; trials node only when `trials` exists or the structure is agent-*; missing required parts as ghost nodes labelled "missing".
2. dagre LR layout (TB under 768 px). Node colours: grader kinds per T1 tokens.
3. Tab "Flow" on `/catalog/[id]` and `/inspect`. Clicking a node opens the matching anatomy part panel.
4. Snapshot tests of the graph for both seeds and for the `promptfoo`, `elevenlabs-simulation-test` and `inspect_task` fixtures.

## Acceptance
- E12 shows a code grader (script) and an LLM judge, the gate on its criterion, and the banded aggregation.
- A pairwise eval (write a tiny test card) shows two system outputs feeding the judge and a swap-order note.

## Out of scope
Running evals.
