# T3 — Anatomy view (theory)

**Depends on:** T1. **Can run in parallel with:** T2. **Branch:** `t3-anatomy-view`.

## Goal
`/[locale]/anatomy`: an interactive diagram of the 16 parts of an eval, the centrepiece of the site.

## Read first
`docs/ARCHITECTURE.md` (Diagrams → Anatomy view, Conventions), `content/anatomy.json`, `content/sources.json`, `docs/reference/agents-visualizer/src/components/canvas/*` (xyflow patterns).

## Deliverables
1. `src/components/anatomy/AnatomyDiagram.tsx` (@xyflow/react): five group bands left→right, parts positioned by a fixed layout table in code (stable, hand-tuned, not auto-layout), the `decision` terminal node, edges from `relations` (flow solid, control dashed, defines dotted, with labels on hover/focus). Required/conditional/recommended shown by a text badge, not colour alone.
2. The component accepts an optional `overlay?: DecomposedEval['coverage']` prop (used by T4) that adds a status badge per node; build it now with a story/test using a hand-written coverage object.
3. Side panel `PartPanel.tsx`: name, level (+ note or condition), one line, explanation, why it matters, best practices, common mistakes, the running example, synonyms ("also called…"), and sources as citations linking to `/sources#id` and the external URL.
4. Mobile (< 768 px): the diagram becomes a vertical list grouped by band with the same panel as a sheet; the diagram stays available behind a toggle.
5. Keyboard: Tab through nodes in band order, Enter opens the panel, Esc closes it. `aria-label`s from content.
6. Intro text above the diagram from `anatomy.json.runningExample` + group questions.

## Acceptance
- Both locales render all 16 parts and 17 relations; every source id resolves.
- Lighthouse accessibility ≥ 95 on `/es/anatomy`.
- Screenshot (desktop + 375 px) in the PR.

## Out of scope
Loading a concrete eval (T4).
